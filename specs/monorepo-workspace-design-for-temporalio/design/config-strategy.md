# Config strategy

Verified at commit: `051de464a`

This document says how each config site of the single-package repo changes in the `apps/ui` layout ([target-layout.md](target-layout.md)). The spike changed most of these sites in practice. [spike-results.md](spike-results.md) lists what it had to change.

## The rule: a shared base or a per-package copy

- **Shared base in `packages/config`:** a config that holds policy and no paths. This applies to TypeScript compiler options, eslint rules, prettier options and stylelint rules. Each package extends the base and adds only its paths. A policy change then happens one time.
- **Per-package copy:** a config that holds paths or a tool's entry point. This applies to `svelte.config.js`, `vite.config.ts`, `vitest.config.ts`, `tailwind.config.ts`, `.storybook/*` and `playwright.config.ts`. These stay in the package that owns the tool (see the tool-owner table in target-layout.md). A shared base for them would hide the paths that make each package different.
- **Repo root:** a config that applies to the repo, not to a package: `.husky/`, `.lintstagedrc.json`, `.github/`, `.editorconfig`, `pnpm-workspace.yaml`.

## Why one alias map

The three alias declarations already disagree (claims ledger, row 4). `$types` points to `src/lib/types` in `svelte.config.js:31`, and to `src/types` in `vite.config.ts:28` and `vitest.config.ts:52`. `src/types` does not exist. The 14 imports of `$types` are type-only, so the compiler removes them, and the wrong mapping never fails a build or a test. A move to `apps/ui` changes all three files. The move is the correct time to keep one map, in one file that the three configs import.

## Interaction with the toolchain upgrades

- **SvelteKit 3** changes `$lib` to `#lib`, moves config into `vite.config`, and makes `svelte-package` rewrite `#lib`. If the move to `apps/ui` comes first, the upgrade changes one alias map, not three.
- **Vitest 5** removes the workspace file and uses `test.projects`. A root `vitest.config.ts` with `projects: ['apps/*', 'packages/*']` can come with the upgrade. It is not part of this design.
- **Tailwind 4** replaces the `content` glob with `@source` per package (sites 5 and 6). It does not block this design.
- **Storybook 11** keeps one Storybook per package. Site 7 does not change.
