Verified at commit: `051de464a`

### Example: a forbidden import in Io (R4.S1)

A developer adds `import { translate } from '$lib/i18n/translate'` to a file in `packages/io/src/`.

1. `pnpm --filter @temporalio/io check` fails, because `$lib` does not resolve in `packages/io`.
2. If the developer uses the relative path `../../../apps/ui/src/lib/i18n/translate`, eslint reports `import-x/no-restricted-paths` and `import-x/no-relative-packages`.
3. The `lint` and `check-types` jobs fail, so the `ci-gate` job fails, and the PR cannot merge (ci-and-release.md).

### The baseline of rule B5

Rule B5 has 6 violations today. The check turns on with an allowlist of these 4 files (an `except` entry in the zone). A follow-up PR moves the shared types from `src/lib/components/workers/serverless-worker-form/` and `src/lib/components/common-errors/common-errors-data` into `src/lib/types` or `src/lib/utilities`, and then it removes the allowlist. Rule B5 does not block Stage 1.

## Why not dependency-cruiser or Sheriff

- **dependency-cruiser** draws a full graph and has rules for cycles and orphans. It is a new dependency with a separate config. It reads `.svelte` files only through a pre-compile step. The rules above do not need a graph, so it is not needed at the start. It is a good later addition if the team wants cycle detection in the app.
- **Sheriff** has module tags and barrel-file rules. It targets TypeScript projects and has no Svelte support in its documentation. It is not a good fit.

`eslint-plugin-import-x` runs in the lint job that exists today, and through `eslint-plugin-svelte` it reads `.svelte` files. It needs no new tool.

## Compatibility with Turborepo

The rules do not depend on a task runner. If the team adds Turborepo later, Turborepo uses the same workspace dependency graph that rules B1 to B8 keep correct. A correct graph is what makes the Turborepo cache and the `--affected` filter safe.
