# Migration plan

Verified at commit: `051de464a`

This document gives the ordered steps from the single-package repo to the layout in [target-layout.md](target-layout.md). Each step is one PR on `main`. Each PR is green before it merges, and each has a rollback point. The work starts after the current code freeze (#4201).

## Rules for every step

- **Moves use plain `git mv`, in a PR that has no content changes.** Path fixes go in a second commit in the same PR. Git then detects each file as a rename, and `git log --follow` and `git blame` keep the history. History is never rewritten.
- **Each PR is green on its own.** `ci-gate` passes, and `pnpm build:server` writes `server/ui/assets/local`.
- **The published surface does not change in 2.x.** Each PR that touches packaging compares the `exports` of a `pnpm pack` of `@temporalio/ui` before and after the change. Only additions are allowed.
- **Releases during Stage 1.** Releases continue in every step. No step publishes to npm (decisions.md, decision record 11), so no release freeze is necessary. Step 1.1 keeps the root `package.json` public, and step 1.2 moves the release actions to `apps/ui/package.json` in the same PR that makes the root private. From step 1.3, the `cloud-ui` pack flow installs both tarballs (ci-and-release.md, `cloud-ui` change 3).
- **Open PRs.** 56 PRs are open today (`gh pr list`). A move PR merges at a low-traffic time, with a notice to the team one day before. Git rename detection lets most open PRs rebase without conflicts.

## What Stage 2 and Stage 3 defer

| Stage | Item                                      | Why it waits                                                                                                                                                                                                                                                                                                                                                          |
| ----- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2     | Go module publishing from `temporalio/ui` | The module path must become `github.com/temporalio/ui/server/v2`, with tags `server/vX.Y.Z`. The old path `github.com/temporalio/ui-server/v2` can be served from this repo only through a vanity `go-import` meta tag with a subdirectory (Go 1.25 and later). `temporalio/cli` pins `v2.56.4` of the old path. This is a separate decision with separate consumers. |
| 2     | Retire the `ui-server` mirror             | `ui-server` commits built assets so that `go get` works offline. Other projects (Prometheus, Argo CD, Gitea, Jaeger) ignore built assets in git and embed them at build time. That change needs Stage 2 first.                                                                                                                                                        |
| 2     | Move `server/` to `apps/server`           | The folder sets the new module path and the tag prefix. Decide the folder and the module path together, so the `ui-server` sync, the workflow paths and the tags change one time (target-layout.md, decision record 1).                                                                                                                                               |
| 2     | `go.work`                                 | The Go docs advise against a committed `go.work`. CI runs with `GOWORK=off`. Nothing in Stage 1 needs it.                                                                                                                                                                                                                                                             |
| 3     | `cloud-ui` extension seams                | A defined place where `cloud-ui` adds private code to the public app, for example a file-present check or a build flag, in place of SHA vendoring.                                                                                                                                                                                                                    |
| 3     | npm publishing                            | Nobody installs `@temporalio/ui` from npm today (decisions.md, decision record 11). When the team decides to publish, ci-and-release.md, "Later: npm publishing (Stage 3)", gives the setup and the first publish of `@temporalio/io`.                                                                                                                                |
| 3     | Snapshot publishing                       | Publish each `main` commit as `@temporalio/ui@<version>-main.<sha>` with the dist-tag `main`. `cloud-ui` can then install from npm in place of the `.tgz` flow. This needs Changesets or pnpm `versioning` for snapshot versions.                                                                                                                                     |
| 3     | Io replaces Holocene                      | The team plan, not part of the split. Each Holocene component that Io replaces moves into `packages/io` without its app imports, and rule B1 enforces it (target-layout.md, decision record 1). Holocene does not get its own package.                                                                                                                                |
